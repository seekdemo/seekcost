# 股票池修复与本地压测记录

## 修复

行业与概念可能使用同名分类。原 themeSummary 直接连接两组标签，造成两处标签列表使用重复 React key。现在在展示层稳定去重，保留数据库分类，不使用数组下标掩盖问题。

## 验证

- 重叠分类回归：修复前明确复现 same-key 错误；修复后 desktop/tablet/mobile 三项通过，包含行情回退、涨跌幅排序、窄屏无溢出检查。
- `npx tsc --noEmit` 通过。
- 导入和研究草稿后端测试 4 项通过；`git diff --check` 通过。
- 实际 demo 股票池 1440 / 390 宽度均渲染 346 行，无重复 key、无 pageerror、无横向溢出。控制台仍有普通 demo 探测管理员入口时的 403（权限拒绝），不属于股票池错误。
- 截图位于忽略目录 `frontend/test-results/watchlist-fixed-{1440,390}.png`。

## 压测

本机 Next 开发代理 → FastAPI → SQLite，已有 346 标的。单个 demo 身份，经 3000 端口，预热后混合请求 stocks / research-guides / alerts/notifications / auth/me，各占 25%。每档 100 请求，超时 10 秒，客户端并发有界。不执行写操作、不压测外部行情接口。

| 并发 | 请求数 | 错误 | P50 ms | P95 ms | 最大 ms | 请求/秒 |
|---|---:|---:|---:|---:|---:|---:|
| 1 | 100 | 0 | 15.1 | 25.2 | 87.4 | 56.3 |
| 5 | 100 | 0 | 17.1 | 27.4 | 48.7 | 251.9 |
| 10 | 100 | 0 | 35.8 | 385.0 | 430.5 | 124.6 |
| 20 | 100 | 0 | 43.4 | 1144.9 | 1230.3 | 71.6 |

复跑：在 backend 中设置 LOAD_USERNAME / LOAD_PASSWORD，运行 `.venv/bin/python scripts/load_demo_reads.py`。脚本限定 localhost，遇请求错误停止后续档位，并核对股票列表数量。

结论：本次已知渲染缺陷修复，测试范围内无失败请求；20 并发存在明显延迟上升。短时单身份开发环境基线不是生产容量承诺，不覆盖长时稳定性、多账户、写入争用、外部行情可用性。上线前需在目标服务器 production 构建及实际数据库配置上再次验证。
