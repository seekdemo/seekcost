# SeekCost 产品功能梳理与未来路线图

> 文档状态：当前产品基线
> 更新日期：2026-08-09

## 一、产品定位

SeekCost 是一套面向个人投资者的全资产投资管理与决策辅助系统。

它不试图替代同花顺、富途等行情终端，也不建设公开社区或内容分发平台。产品的核心目标是帮助用户持续回答以下问题：

- 我现在拥有什么，真实成本是多少？
- 为什么考虑买入或继续持有？
- 什么情况会证明当前判断错误？
- 实际交易是否按照事前计划执行？
- 这次结果能够怎样改进下一次决策？

产品围绕一条明确闭环组织：

```text
资产事实 → 候选标的 → 公司研究 → 投资决策 → 交易执行 → 结果复盘 → 策略迭代
```

## 二、现有核心功能

### 1. 投资工作台

入口：`/`

工作台通过聚合接口展示当前用户真正需要处理的事项：

- 接近观察价或进入击球区的候选标的
- 即将到期的事件与研究复核
- 长时间没有更新的股票池标的
- 缺少核心投资逻辑或证伪条件的标的
- 当前执行中的交易计划
- 最近完成但尚未复盘的交易

工作台的定位是行动队列，而不是资讯首页。当前方向已经正确，但还需要加强事项优先级和后续动作闭环。

### 2. 全资产投资目录

入口：`/portfolio`、`/assets`

SeekCost 当前支持三类资产，并保持不同的核算边界：

| 类型 | 示例 | 主要记录方式 |
| --- | --- | --- |
| 市场投资 | 股票、ETF、Token | 数量、成本、现价、市值与盈亏 |
| 防御与实物 | 现金、定存、债基、黄金、房产、收藏品 | 本金、当前价值与持有状态 |
| 能力与工具 | GPT 会员、软件、课程、获客投入 | 累计投入、归因回报与复盘 |

已有能力包括：

- 资产创建、编辑、归档和删除
- 自定义快捷创建项
- 标签管理
- 计划投入金额
- 市场、类别和投资区域区分
- 资产详情页
- 交易记录和交易计划关联
- 成本回收进度、已实现盈亏和未实现盈亏
- 券商现金单独分类

能力投资不进入传统证券净资产，也不套用股票盈亏公式。后续应优先保证账本准确性，而不是继续增加视觉模块。

### 3. IBKR 成本与交易账本

入口：`/import/ibkr`、`/trade`、资产详情页

当前支持：

- IBKR Activity Statement 导入
- 股票交易解析
- 存入和取出资金解析
- 重复导入去重
- 持仓成本同步
- 交易批次管理
- 买入批次与卖出批次关联
- 券商真实成本
- 决策成本
- 已实现和未实现盈亏
- 手续费
- 盈利分配到当前资产、其他资产或现金储备
- 交易修改后自动重算相关数据

这是 SeekCost 最重要的差异化能力之一。现阶段仍需补充公司行动、多币种成本、税费、汇率时点、异常修正和完整审计轨迹。

### 4. 候选标的股票池

入口：`/watchlist`

当前功能包括：

- Radar、Conviction、Strike 三阶段管理
- 股票、ETF、指数等标的管理
- 美股、港股和 A 股市场区分
- 行业、概念和用户分类
- 按涨跌幅排序
- 搜索、全选和批量操作
- 批量修改阶段
- 批量添加行业和概念
- CSV 导入与导出
- 用户主动上传分类文件、预览匹配并确认应用
- 股票池归档
- 财报日历
- 财报日期自动同步
- 速记、置顶、删除和升级为研究

财报日历当前使用 Yahoo 获取美股、港股日期，使用东方财富获取 A 股预约披露日期。ETF、指数和加密货币等没有公司财报的对象会自动跳过，用户手工确认的日期不会被自动同步覆盖。

股票池应保持为从关注到决策的中间层。分类上传属于整理用户自己的数据，不应演变为股票推荐。

### 5. 候选标的公司研究档案

入口：`/watchlist/[id]`

页面围绕五个固定研究区块组织：

1. 公司概览
2. 行业与护城河
3. 增长与财务质量
4. 风险与证伪
5. 估值与决策锚点

每个区块支持：

- 当前判断
- Markdown 编辑与预览
- 证据来源
- 待验证问题
- 上次复核
- 下次复核
- 复核备注

同时提供当前价格、观察价、合理价、目标价、计划资金、研究完成度、关联研究、速记、K 线和量价观察。

该页面已经从字段录入表转变为帮助用户彻底理解一家公司、维护证据并形成决策的研究档案。

### 6. K 线与量价观察

候选标的详情页当前支持：

- 日 K 线和周期切换
- 成交量
- MA5、MA10、MA20、MA120、MA250
- 指标开关
- 键盘查看不同交易日
- OHLC 数据
- 加载、无数据、数据过期和提供商失败状态
- 数据来源与更新时间

量价观察包括均线位置、年化波动率、ATR、最大回撤、相对成交量、支撑阻力和价格空间。所有结果展示计算依据，不生成确定性买卖建议。

当前能力属于量化观察基础设施，尚不等于完整量化系统。现阶段还不具备规则回测、信号历史追踪、策略收益归因和组合风险分析。

### 7. 研究库

入口：`/research`

研究库是投资判断的沉淀层，当前支持：

- 快速研究、公司研究、投资逻辑、决策记录和交易复盘
- 草稿、待验证、已验证、已证伪和已归档状态
- 信心等级
- 下次复核时间
- 星标
- 股票、资产、交易计划和交易记录关联
- 标签和研究专题
- 创建时间与更新时间区分
- 卡片视图和文稿视图
- 按更新时间、创建时间和复核时间排序
- 按类型、状态、标的、专题和标签筛选

编辑体验包括：

- Markdown 默认编辑
- 富文本模式
- AI 回答粘贴
- Markdown 预览
- 桌面端编辑与预览分栏
- 移动端编辑与预览切换
- 标题、列表、引用、代码、表格和链接工具
- 封面图片和低饱和无图封面
- 图片插入和调整
- 自动保存
- 保存失败时保留本地草稿

研究详情页支持固定 URL、阅读进度、文章目录、股票和专题链接，以及桌面侧边评论、平板折叠评论和移动端评论抽屉。

划词评论支持文字高亮、评论定位、回复和 Emoji。评论定位是个人批注和复核记录，不是社区互动。

### 8. 研究专题

入口：`/research/topics`

当前支持：

- 专题独立页面
- 专题简介和 Markdown 编辑
- 专题下的研究列表
- 专题星标
- 研究与专题之间的超链接
- 专题创建、修改和删除

后续应增加专题时间线和研究结论变化，使专题不只是普通文件夹。

### 9. 交易计划

交易计划当前包括：

- 目标仓位和最大仓位
- 建仓区间
- 止损和分批止盈
- 支撑与阻力
- 买入策略
- 卖出策略
- 执行纪律
- Active、Completed、Abandoned 状态

目前交易计划与研究结论、实际交易和最终复盘的连接还不够强，仍偏向独立表单。

### 10. 交易执行与复盘

入口：`/trade`、`/review`，旧 `/board` 保留兼容

交易执行支持买入、卖出和 T 交易，采用加权平均成本，可按买入批次分配卖出数量，并在修改交易后重算资产状态。

复盘当前支持：

- 7 天、30 天、90 天、本年和自定义范围
- 按资产筛选
- 总买入、总卖出、净盈亏和手续费
- 交易笔数和胜率
- 单个资产表现
- 已实现和未实现盈亏
- P&L 曲线
- 买卖分布
- 交易时间线

当前复盘仍偏重结果展示。后续需要区分判断错误与执行偏差，并将错误模式反馈到下一次决策。

### 11. 现金、个人财务和资金数据

次级入口：`/cash`、`/finance`、`/dashboard`

当前包括现金账户、券商现金、工资配置、收入记录、负债、净资产、汇率转换、现金储备和 IBKR 资金流。

这些功能属于投资系统的基础数据层，应该统一归入“资金与数据”，不与核心决策流程争夺一级导航空间。

### 12. 账号、隐私、国际化和响应式体验

当前支持：

- 用户名和密码注册登录
- 不依赖邮箱服务
- 英文默认
- 简体中文、繁体中文、日语、西班牙语和法语
- 多主题色
- 桌面、平板和手机适配
- 私有数据按当前用户隔离
- 旧公开研究接口返回 `410 Gone`
- 不建设公开社区、发现流、作者和热度分发
- 不接入 BLEX，两个产品保持完全独立

国际化框架已经建立，但仍有少量硬编码文案、旧导航偏好和遗留类型需要清理。

## 三、产品真正应该坚持的核心

### 1. 投资账本真实可靠

必须持续保证 IBKR 成本、持仓数量、交易批次、手续费、现金、币种以及已实现和未实现盈亏准确可信。

### 2. 全资产但不混账

- 股票和 ETF 使用市场成本与盈亏
- 现金、房产和黄金使用资产价值
- GPT 会员、课程和软件使用累计投入与归因回报
- 能力投资不能伪装成证券收益

### 3. 公司研究和决策锚点

系统要帮助用户理解公司如何赚钱、增长来自哪里、护城河是否真实、风险是什么、什么情况需要认错，以及什么价格和仓位值得执行。

### 4. 交易计划与执行复盘闭环

研究必须能够影响交易计划，交易必须能够返回复盘，复盘结果必须能够改进下一次决策。

### 5. 量化观察基础设施

当前阶段应积累可靠的价格历史、均线、波动率、回撤、成交量、支撑阻力、研究时点快照和事后结果，而不是急于生成 AI 买卖建议。

## 四、当前主要问题

### 1. 页面和路由职责仍有重叠

一级导航已经收敛为工作台、投资、决策和复盘，但 `/dashboard`、`/portfolio`、`/finance`、`/cash`、`/board`、`/notes`、`/research`、`/watchlist` 和 `/decision` 等内部入口仍存在职责重叠。

应该明确：

- 工作台：今天要做什么
- 投资：我拥有什么、成本是什么
- 决策：我正在考虑什么
- 复盘：过去发生了什么、学到了什么
- 资金与数据：现金、财务、导入和汇率

旧路径可以保留兼容跳转，但不应继续发展成独立产品概念。

### 2. 旧“博弈”语义仍有残留

代码和旧页面中仍存在“博弈仪表盘”“交易与博弈引擎”“心理成本”“零成本”和“避风港”等名称。

建议逐步统一为：

- 心理成本 → 决策成本
- 博弈引擎 → 成本与利润分配引擎
- 避风港 → 现金储备
- 零成本 → 成本回收进度
- 博弈仪表盘 → 投资总览或资产账本

### 3. 研究兼容层和遗留社交结构较多

当前仍存在旧 `visibility` 枚举、收藏表、社交表、分享表以及部分前端 `Record<string, unknown>` 接口。这些结构在迁移期间可以保留，但不应继续进入新产品逻辑。

### 4. 自动保存还不是完整编辑事务

未来仍需要补充保存版本号、并发冲突保护、请求乱序处理、最后成功保存时间、离开页面提示和断网恢复。

### 5. 复盘与研究之间尚未真正打通

当前已经可以关联研究、资产、交易计划和交易记录，但尚未自动形成交易前判断快照，也没有系统化计算计划与实际执行偏差。

## 五、未来优化路线

### P0：数据准确性与产品边界

#### 1. 统一事实来源

- 券商真实成本以 IBKR 导入为准
- 当前价格标明来源和时间
- 研究、计划和复盘以服务端为唯一事实来源
- 本地存储只保存界面偏好
- 每个金额明确币种和汇率时点
- 能力投资不进入证券盈亏

#### 2. 完善 IBKR 对账

优先补充分红、拆股、公司行动、外汇转换、税费、利息、现金变动、导入异常修正、导入前后余额核对，以及可重复、可撤销的导入批次。

#### 3. 收敛旧社交代码

- 从应用路由移除无用接口
- 删除未挂载的分享、关注、通知和排行榜业务代码
- 删除前端遗留的公开和空间权限选项
- 将 `NoteVisibility` 限定为迁移兼容字段
- 保留历史数据库表，避免破坏性数据删除
- 持续验证旧公开链接返回 `410 Gone`

#### 4. 统一导航和命名

用户可见的一级概念固定为工作台、投资、决策和复盘。内部统一使用资产目录、股票池、研究库、交易计划、交易记录、复盘记录以及资金与数据。

### P1：打通研究、计划、交易和复盘

#### 1. 研究自动形成决策卡

每项重要研究明确展示当前结论、证据、证伪条件、估值区间、计划仓位、复核时间和关联交易计划。

#### 2. 交易前保存决策快照

录入交易时保存当时的研究版本、核心逻辑、证伪条件、价格指标、计划价格、计划仓位和信心等级，避免复盘时只能看到后来被修改的内容。

#### 3. 自动对比计划与事实

复盘需要计算计划价格与实际成交价、计划仓位与实际仓位、执行纪律、证伪条件和最终结果之间的偏差。

#### 4. 工作台增加优先级

推荐排序：

1. 会改变仓位的事项
2. 即将到期的研究和财报
3. 已经交易但没有复盘的事项
4. 逻辑不完整的标的
5. 长期没有更新的观察对象

### P1：将股票池继续升级为研究入口

继续强化公司研究完成度、研究缺口、证伪条件状态、价格与估值区间关系、研究更新时间、财报复核提醒和速记来源链路。

ETF 和指数不应套用公司研究模板，应增加跟踪指数、费率、成分集中度、规模流动性、跟踪误差、分红方式和宏观暴露等字段。

### P1：完善全资产体系

不同资产应使用不同的最小字段：

| 资产类型 | 关键字段 |
| --- | --- |
| 股票、ETF | 数量、成本、现价、币种、交易记录 |
| Token | 数量、钱包或平台、成本、估值时间 |
| 现金 | 账户、余额、币种、可用性 |
| 黄金、房产 | 持有数量、当前估值、估值日期 |
| GPT、软件 | 周期、累计支出、使用频率、归因收益 |
| 课程 | 购买成本、完成度、应用结果 |
| 自定义资产 | 用户定义字段、估值方式、复核周期 |

### P2：建立真正的量化研究体系

#### 阶段一：数据可靠

- 统一交易日和时区
- 记录行情来源和更新时间
- 处理缺失数据和公司行动
- 保存研究时点指标快照

#### 阶段二：规则透明

将指标抽象成版本化规则，保存规则名称、参数、触发条件、观察结果、适用市场和生成时间。

#### 阶段三：结果评估

统计信号触发后的 5 日和 20 日表现、最大有利波动、最大不利波动，以及不同市场环境下的表现。

#### 阶段四：策略研究

最后再建设回测、纸面交易、策略对比、风险预算和组合级别信号。不直接建设自动下单或黑箱推荐。

### P2：提升研究生产效率

- 所有长文本字段统一 Markdown 编辑体验
- 自动保存版本管理
- 保存冲突和断网恢复
- 粘贴 AI 内容时保留来源
- 研究模板
- 快捷插入股票、资产和交易记录
- 研究引用与反向引用
- 研究历史版本
- 复核时对比上次修改
- 研究专题时间线
- 批注和评论管理

评论继续保持个人批注定位，不发展为社区评论。

### P2：开源工程治理

- 增加明确的开源许可证
- 清理示例数据库和真实数据
- 检查 `.env`、日志、CSV 和导入文件
- 完善英文与中文 README
- 增加最小演示数据生成脚本
- 统一 PostgreSQL 与本地开发数据库说明
- 将核心 API 改成完整 TypeScript 类型
- 增加 CI
- 增加数据库迁移升级和回滚检查
- 明确行情数据供应商限制
- 增加安全策略
- 删除未挂载旧代码
- 不引入 BLEX 或其他平台依赖

## 六、明确不建设的功能

以下功能会让 SeekCost 再次膨胀，应保持边界：

- 公开发现流
- 创作者主页
- 关注、点赞和粉丝体系
- 热度排行榜
- 社区通知
- 内容推荐
- 股票资讯聚合
- 实时行情终端
- 复杂选股器
- AI 确定性买卖建议
- 自动跟单和自动下单
- 自动发布到其他平台
- 多人工作空间和协作权限
- 复杂的跨用户收藏体系

SeekCost 可以允许用户主动上传文件、整理分类和记录研究，但不转向内容分发或行情平台。

## 七、产品衡量标准

未来不再以功能数量作为主要标准，而应围绕三个问题优化：

1. **账本是否可信**：用户能否准确知道自己的成本、持仓、现金和盈亏。
2. **判断是否可解释**：用户能否清楚知道自己为什么买，以及什么情况下应该认错。
3. **复盘是否能改变下一次行为**：系统能否帮助用户发现重复错误并改进策略。

推荐的总体建设顺序：

```text
数据与成本准确性
→ 研究、计划、交易和复盘打通
→ 研究模板与版本历史
→ 组合风险与量化评估
→ 开源工程治理
```

SeekCost 应稳定地发展为个人投资管理与决策辅助系统，而不是功能繁杂的股票社区、行情工具或外部内容平台附属产品。
