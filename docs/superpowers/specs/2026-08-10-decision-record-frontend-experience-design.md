# 决策记录模块前端体验升级设计

**日期：** 2026-08-10

**状态：** 已完成产品设计确认，待实施计划

**范围：** SeekCost 决策记录模块的前端编辑、阅读、研究库、专题、评论与批注体验

## 1. 背景

SeekCost 的核心定位是投资管理与决策辅助系统。决策记录承担研究沉淀、投资判断、复核与复盘的长期记录职责。现有模块已经具备 Markdown、富文本、研究元信息、评论和批注等能力，但交互分散，编辑与阅读状态不够清晰，移动端和不同屏幕尺寸下的体验也不一致。

本次改造聚焦“文档编辑和文档浏览达到飞书级别的顺畅体验”，不扩大产品边界，不重做后端文档模型。

## 2. 目标与非目标

### 2.1 目标

- 让用户可以直接粘贴 AI 回答，并快速整理成结构清晰的研究文档。
- 默认提供直观的视觉化编辑，同时保留 Markdown 源码编辑和预览能力。
- 明确分离阅读态和编辑态，降低界面噪声。
- 统一研究库、研究详情、专题、评论与批注的视觉和交互语言。
- 在桌面、平板和手机上提供协调、完整且不遮挡内容的响应式体验。
- 保持现有文章、接口和数据格式兼容，避免不必要的数据迁移。

### 2.2 非目标

- 不引入块级 JSON 文档模型或复杂数据库迁移。
- 不实现多人实时协作、实时光标、在线成员或文档权限协作。
- 不新增公开社区、关注、推荐、热度分发或跨用户互动。
- 不接入 BLEX，也不提供跨平台同步或发布。
- 不整体重做股票池、资产和交易模块，仅保留它们与研究记录之间的跳转关系。

## 3. 产品范围与信息架构

本轮覆盖以下页面和交互：

- `/decision`：决策总览
- `/research`：研究库
- `/research/new`：新建研究
- `/research/[id]`：研究详情
- `/research/topics`：研究专题
- `/research/topics/[id]`：专题详情
- 研究评论、划词评论、批注定位、阅读和编辑状态

主路径保持简单：

```text
决策总览 → 研究库 → 研究详情
                 ↘ 研究专题
```

决策总览只呈现需要用户处理的事项，包括待判断标的、待验证研究、到期复核、缺少证伪条件的研究，以及最近交易但尚未复盘的记录。它不承担资讯流或推荐流职责。

## 4. 核心体验原则

1. **阅读优先。** 进入研究详情默认看到安静、稳定的阅读页面，而不是表单。
2. **编辑沉浸。** 点击编辑后再进入完整编辑环境，减少元信息和评论对写作的干扰。
3. **渐进呈现。** 常用操作直接可见，低频操作通过浮动工具栏、插入菜单或更多菜单出现。
4. **状态可信。** 自动保存、失败、重试和未保存状态必须清楚，不能让用户猜测内容是否已保存。
5. **兼容优先。** 新体验复用现有 `content + format`，旧 Markdown 和富文本文章继续可读可编辑。
6. **响应式而非压缩式。** 小屏幕重新组织操作，不只是缩小桌面布局。

## 5. 编辑体验

### 5.1 编辑状态

研究详情默认处于阅读态。点击“编辑”进入沉浸式编辑状态：

- 顶部只保留返回、标题、保存状态、模式切换和“完成”。
- 标题支持直接点击和输入，不再打开额外弹窗。
- 正文采用舒适阅读宽度和稳定的段落节奏。
- 可开启专注模式，暂时隐藏元信息和侧边内容。
- 点击“完成”保存当前内容并返回阅读态。

新建研究页面直接进入编辑状态，并与详情页复用同一编辑器外壳和工具栏。

### 5.2 编辑模式

编辑器提供两个明确模式：

- **视觉化编辑：** 默认模式，适合日常写作、整理 AI 回答和快速排版。
- **Markdown 源码：** 面向熟悉 Markdown 的用户，提供源码编辑与预览。

模式切换必须保留当前内容和光标上下文，不能触发保存后退出编辑。旧文章继续根据现有 `format` 打开，视觉化编辑与 Markdown 转换以现有兼容能力为基础渐进增强。

### 5.3 工具栏与插入

编辑器平时保持简洁。选中文字时显示浮动工具栏，提供：

- 粗体、斜体、删除线
- 标题层级
- 有序列表和无序列表
- 引用与代码
- 链接
- 图片
- 分割线

输入 `/` 打开插入菜单，支持标题、列表、引用、代码块、表格、图片和分割线。插入菜单只是前端快捷入口，不引入新的块级存储模型。

### 5.4 粘贴 AI 回答

粘贴流程服务于高频的 AI 内容整理场景：

1. 清理来源页面附带的字体、字号、颜色和无意义 HTML。
2. 尽量识别标题、列表、引用、代码块、链接和段落结构。
3. 保留原文内容和语义，不自动改写或总结。
4. 粘贴完成后显示短暂的“已整理粘贴内容”提示，并允许撤销。

如果无法安全转换，编辑器应退化为纯文本粘贴，不能丢失剪贴板内容。

### 5.5 快捷键

- `Command/Ctrl + Enter`：保存并完成编辑
- `Command/Ctrl + K`：插入或编辑链接
- `Command/Ctrl + Z`：撤销
- `Command/Ctrl + Shift + Z`：重做
- `/`：打开插入菜单
- `Escape`：关闭浮层，或退出专注模式

## 6. 阅读体验

### 6.1 文章布局

研究详情采用清晰的文章外壳：

- 顶部展示返回上下文、标题、状态、星标和核心操作。
- 标题下方使用轻量元信息栏展示关联标的、专题、标签、创建时间、更新时间和复核时间。
- 正文最大宽度约 760px，确保长文阅读舒适。
- 表格和代码块只在自身容器内横向滚动，页面本身不得横向溢出。
- 图片自适应正文宽度，并保留原始宽高比例。

顶部提供细微阅读进度反馈。页面返回研究库时恢复原来的搜索、筛选、排序和滚动位置。

### 6.2 目录

桌面端右侧提供自动生成的文章目录：

- 根据正文标题层级生成。
- 当前阅读章节高亮。
- 点击条目平滑滚动到对应章节。
- 文章没有足够标题时不显示空目录。

目录和评论共用一个右侧面板，通过标签切换，避免同时挤压正文。

## 7. 评论与批注

### 7.1 划词评论

- 选中文字后，在选区附近显示“添加评论”。
- 选区和按钮在用户点击其他相关操作前保持稳定，避免选完即消失。
- 高亮使用独立于主题色的低饱和暖色，并保证深浅主题下的文字对比度。
- 评论提交后，对应文字持续保留底色。
- 点击高亮文字可定位并打开对应评论。

### 7.2 评论浏览

- 桌面端在右侧“评论”标签中查看与当前段落对应的评论。
- 用户可以切换为文章底部的“全部评论”视图。
- 手机和平板使用底部抽屉，不常驻占用正文宽度。
- 评论继续支持回复和 Emoji，并清晰展示现有锚点状态。
- 原文位置已变化的评论保留引用文本，但在默认列表中弱化，避免干扰当前阅读。
- 历史评论继续兼容现有权限和数据，不改变后端业务规则。

### 7.3 定位与异常状态

如果文章修改后原选区无法精确定位，评论仍保留在评论列表中，并标记为“原文位置已变化”，不能静默丢失。点击后定位到可识别的最近段落；无法定位时显示原引用文本。

## 8. 研究库与专题

### 8.1 研究库

顶部操作区统一承载：

- 搜索
- 全部、星标、待验证、待复核、已归档
- 研究类型、标的、专题和标签筛选
- 更新时间、创建时间和复核时间排序
- 卡片视图和文稿视图切换
- 新建研究

研究卡片优先展示标题、结论摘要、状态、关联标的、下次复核和更新时间。整张卡片可点击；星标和更多操作拥有独立点击区域，避免误触。相同视图中的卡片保持统一高度和信息密度。

移动端保留搜索和新建，其他筛选项收进底部筛选抽屉。筛选条件需要可见、可清除，并在返回列表时保持。

### 8.2 研究专题

专题页重点展示专题名称、说明、研究数量和更新时间。专题详情以研究列表为主，减少装饰性统计和重复卡片。所有专题链接使用固定地址，并提供明确的返回研究库路径。

## 9. 响应式设计

### 9.1 桌面端

- 使用宽内容区和可切换右侧面板。
- 正文居中，目录或评论面板不遮挡正文。
- 顶部操作栏保持可用，但视觉上弱化。

### 9.2 平板端

- 正文占据主要宽度。
- 目录和评论改为抽屉，不保留固定第三栏。
- 编辑工具栏按可用宽度收纳低频操作。

### 9.3 手机端

- 单列正文布局。
- 底部提供编辑、评论和目录三个核心操作。
- 筛选、目录和评论使用底部抽屉。
- 固定顶部栏必须预留安全区域，不能遮挡标题。
- 所有主要触控目标至少 44px。

## 10. 前端组件边界

当前研究库和研究详情的部分逻辑集中在 `frontend/src/app/notes/page.tsx`。本轮只做与体验升级直接相关的拆分，避免无关重构。

建议形成以下职责边界：

- `ResearchLibrary`：搜索、筛选、排序、视图切换和列表状态。
- `ResearchCard` / `ResearchRow`：两种研究列表呈现。
- `ResearchArticleShell`：阅读态页面骨架和响应式布局。
- `ResearchEditorShell`：编辑态页面骨架、标题和保存状态。
- `ResearchEditor`：视觉化编辑、Markdown 模式、粘贴和快捷键。
- `ResearchOutline`：目录生成、章节定位和阅读进度。
- `ResearchCommentPanel`：评论列表、划词评论定位和抽屉切换。
- `ResearchMetaBar`：研究状态、标的、专题、标签和时间信息。

组件通过明确的值、回调和状态对象通信。页面路由负责加载数据和保存，展示组件不直接拼装请求。

## 11. 数据流与自动保存

### 11.1 数据兼容

- 后端继续使用现有 `notes.content` 字符串和 `notes.format`。
- 不新增文档块表、不迁移旧文章。
- 现有 Markdown 和富文本内容继续按照原格式读取。

### 11.2 保存流程

1. 用户输入后立即更新本地编辑状态。
2. 防抖触发自动保存。
3. 每次请求携带前端递增序号，客户端只接受最新保存请求的结果。
4. 保存成功显示“已保存”。
5. 保存失败保留本地内容，显示“保存失败，点击重试”。
6. 用户点击“完成”时立即执行最终保存；失败则留在编辑态。

路由参数变化和列表数据刷新不能重置当前 `editingId`、编辑内容或光标，防止再次出现“自动保存后不能继续编辑”的问题。

## 12. 错误与空状态

- 加载研究失败：保留页面外壳，提供重试和返回研究库。
- 保存失败：不清空编辑器，不自动退出编辑态。
- Markdown 转换失败：保留源内容，并允许回到原模式。
- 评论提交失败：保留输入内容，提供重试。
- 空研究库：说明可以创建的研究类型，并提供单一明确的新建入口。
- 空专题：提示将现有研究加入专题，不展示无意义统计。
- 无目录：隐藏目录标签，而不是显示空面板。

## 13. 可访问性与视觉一致性

- 交互元素具备清晰的键盘焦点样式和可读标签。
- 状态不能只依赖颜色表达，同时使用文字或图标。
- 高亮、正文和辅助文字满足合理的明暗对比。
- 动画保持克制，并尊重系统的减少动态效果设置。
- 深色和浅色主题使用同一信息层级，不因主题切换改变内容含义。

## 14. 验收标准

### 14.1 核心流程

- 用户可以从研究库新建研究、粘贴 AI 回答、整理格式并保存。
- 自动保存后编辑状态、内容和光标保持稳定。
- 用户可以在视觉化编辑和 Markdown 模式之间安全切换。
- 用户可以完成编辑并回到排版稳定的阅读页。
- 目录可以定位章节，评论可以定位原文高亮。
- 返回研究库后搜索、筛选、排序和滚动位置保持。

### 14.2 响应式验证

Playwright 至少覆盖桌面、平板和手机视口下的：

- 研究库搜索、筛选和视图切换
- 新建、编辑、自动保存和完成编辑
- AI 内容粘贴与撤销
- Markdown 模式切换和预览
- 研究详情阅读、目录定位和阅读进度
- 划词评论、评论侧栏与底部抽屉
- 长标题、表格、代码块和图片不造成页面横向溢出

### 14.3 工程验证

- 前端 TypeScript 检查通过。
- ESLint 通过。
- 生产构建通过。
- 现有研究自动保存回归测试继续通过。
- 不要求数据库迁移，也不改变后端研究接口契约。

## 15. 实施约束

- 保留工作区中与本功能无关的用户改动。
- 只拆分和调整决策记录模块直接依赖的前端代码。
- 所有可见文案继续接入现有国际化体系，英文为默认语言，中文可切换。
- 实施过程按页面外壳、编辑器、阅读器、评论、研究库、响应式和回归验证分阶段完成。
